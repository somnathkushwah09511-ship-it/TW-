# Part 3: Google Docs & Doxygen — Collaborative & API Documentation

> **Source**: Lecture slides by Dr. Neeta Nain, MNIT Jaipur

## What's in this section?
Technical writing spans two distinct needs:
1. **Team / Narrative Documentation**: Proposals, specs, project reports, and reviews (**Google Docs**)
2. **Source Code / API Documentation**: Auto-generated API reference manuals directly from code comments (**Doxygen**)

## ⚡ Quick Head-to-Head Comparison

| Feature | Doxygen | Google Docs |
|---------|---------|-------------|
| **Core Purpose** | Automated code & API references | Collaborative documents & reports |
| **Input Source** | Code comments (`/** ... */`, docstrings) | Rich-text cloud editor |
| **Collaboration** | Git / PRs / Code reviews | Real-time live multi-cursor editing |
| **Output Formats** | HTML, LaTeX/PDF, XML, RTF, man pages | PDF, DOCX, Web, ODT, TXT |
| **Visuals** | Call graphs, inheritance trees (Graphviz) | Images, Google Drawings, Lucidchart |
| **Best Used For** | Libraries, SDKs, backend classes | SRS, project summaries, meeting notes |
